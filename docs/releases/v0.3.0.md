# Codex App Server WebUI v0.3.0

Version 0.3.0 turns the Web UI from a remote conversation view into a fuller session control
surface. It combines live runtime and task controls with a substantially faster long-history path,
especially for returning to active sessions from a mobile browser.

## Session control surface

- The conversation header can switch into a composer-free full-screen reading view.
- A live goal panel shows objective, status, elapsed time, and token budget, with typed pause,
  resume, and edit actions.
- Session tools expose cached run time, turns, tool calls, token totals, rollout-sequence health,
  and explicit repair controls.
- Workspace links open in a typed preview before download, while existing workspace-boundary and
  ticket-expiry checks remain enforced.
- Runtime architecture reflects the managed app-server, Desktop interposition, and voice backend
  from live Bridge state instead of a static diagram.

## Long histories and mobile return

- First entry fetches and renders only the latest bounded message window, then lands directly at
  the newest message instead of replaying a long session from its beginning.
- Completed turns retain compact summaries. Deferred intermediate text and tools hydrate only when
  the reader explicitly expands a turn, avoiding enormous automatic payloads.
- Returning to a session supplements the visible tail incrementally. Stable DOM nodes and viewport
  anchors prevent live tool output and image layout from repeatedly moving the mobile scroll
  position or composer focus.
- The session Tools panel includes a refresh action that clears the current browser message cache,
  fetches the newest server window, and follows the latest tail.
- Initial loading and reconnect catch-up are distinguished from an idle session; ordinary model
  waiting continues to use the composer activity treatment.

## Conversation and tool controls

- Tools can collapse every expanded message in the current conversation, including tool results
  that contain images. Images still open in the dedicated zoomable viewer.
- Queue and Steer remain optimistic until an authoritative user message reaches rendered history.
  Text-only, image-only, and text-plus-image inputs now share the same content fingerprint.
- Authoritative messages are consumed one-to-one during pending reconciliation, so duplicate text
  or image submissions cannot all disappear in response to one landed message.
- Message copy, memory citations, structured commands, file diffs, and token usage retain their
  dedicated presentation inside compact turns.

## Bridge and protocol

- Protocol version 34 adds typed goal, session-statistics, file-preview, repair, and managed-service
  control paths used by the expanded Web UI.
- Session parsing and bounded caches provide the recent window, deferred turn details, task
  overview, and statistics without making the browser rescan a complete rollout.
- The one-writer safety model from v0.2.10 remains in place: Bridge-managed app-server ownership is
  scoped to the configured Codex history store and competing private writers are not terminated.

## Validation

- The release WASM demo and browser regression suite cover session controls, large-session paging,
  mobile tail anchoring, cache refresh, message collapse, and multimodal pending handoff.
- The complete Rust workspace suite, formatting checks, strict all-target/all-feature Clippy, and
  macOS/Linux installer syntax checks pass from the release source.
- Production Web UI assets and the optional whisper-enabled release daemon are rebuilt from the
  final tagged source before deployment.
