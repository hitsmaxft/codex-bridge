# Codex App Server WebUI v0.2.0

This release makes the public browser demo and mobile remote-control workflow feel much closer to
the real Codex app-server experience. It expands the demo into a prompt-responsive state machine,
adds editable voice transcription, and removes several sources of mobile composer instability.

## Highlights

- The GitHub Pages demo now selects simulated search, edit, and command workflows from each prompt.
  It continuously refreshes structured tools, queue and steer handoff, withdrawal, cancellation,
  active progress, and final responses through the production frontend.
- Recorded or selected audio is decoded and resampled in the browser to 24 kHz mono PCM. The bridge
  sends that PCM to app-server realtime and inserts the returned transcript at the current composer
  selection, so the user can review or edit it before submission.
- Audio is no longer represented or submitted as a Codex message attachment. The production bridge
  and demo server both reject that obsolete path instead of silently producing the wrong content.
- A right swipe in the mobile conversation opens the Tasks overview directly. Opening the session
  history remains an explicit button action, avoiding gesture ambiguity.
- The mobile composer now keeps its textarea above a stable bottom action row in every focus,
  content, submission, and stop state. Text grows upward, while Submit/Stop and Queue/Steer controls
  use matching widths.
- Pending Queue messages retain the existing blue palette. Steer/follow-up messages use a separate
  bean-green palette with dedicated light and dark theme colors.

## Voice transcription boundary

The bundled app-server schema currently exposes transcription through the experimental realtime v2
flow rather than a standalone dictation method. The Web UI starts a text-output realtime session,
appends PCM audio, waits for `thread/realtime/transcript/done`, then stops the session.

In the bundled app-server tested for this release, realtime v2 rejects ChatGPT-subscription
authentication and requires API-key authentication. The UI reports that limitation directly. It
does not fall back to attaching or submitting the recording. The public demo simulates transcription
locally and never sends recorded data off-page.

## Validation

The release is checked against the rebuilt Rust/WASM demo artifact, JavaScript contract regressions,
the Vite production bundle, the complete Rust workspace test suite, and Clippy with warnings denied.
The production daemon embeds the validated frontend bundle.
