# Codex App Server WebUI v0.2.8

Version 0.2.8 keeps very large sessions responsive, makes browser-to-app-server message handoff
atomic, exposes practical runtime health, and removes the 16 MiB frame ceiling from the optional
Codex Desktop compatibility bridge.

## Bounded large-session loading

- Completed turn details hydrate only when they approach the viewport.
- A shared observer, one active hydration request, and a bounded request interval prevent a fast
  scroll from flooding app-server.
- The regression suite now includes a synthetic session larger than 20 MiB and enforces cold-load,
  warm-load, and response-size baselines.
- Tool output remains deferred until requested, preserving fast navigation without discarding
  history.

## Atomic Queue and Steer reconciliation

- A stable submission ID and source message index survive optimistic rendering, native queue
  negotiation, and Queue-to-Steer conversion.
- The visual outbox clears only after its matching authoritative user item is present in rendered
  app-server history.
- Failed conversions roll back locally, while stream gaps retain bounded polling as a recovery
  mechanism.

## Compact turns and runtime health

- Completed-turn summaries combine duration, tool and edit counts, and right-aligned token usage in
  one compact row; memory citations stay attached to the final response.
- Turn-summary hover uses a subtle upward glow, and message copy controls no longer enlarge the
  bubble or overlap its text.
- The collapsed runtime panel distinguishes browser recording support from server transcription
  readiness and reports peak process memory plus bounded session and tool/project caches.
- Managed whisper startup remains observable until it becomes ready or reports a terminal reason.

## Large Codex Desktop WebSocket responses

- Both the Desktop-facing and app-server-facing WebSocket legs accept frames and messages up to
  64 MiB.
- A bidirectional regression test covers payloads above 16 MiB.
- Production acceptance exercised a 48,314,807-byte thread response containing 115 turns through
  the bridge; oversized-message logs record direction and byte count, never payload content.
- The Desktop path remains a resume-compatibility integration. Private `codex_app` MCP tools are
  disabled by current Desktop builds on external WebSocket transports, which do not export their
  required host pipe. Paginated history remains preferred when the caller supports it.
- The macOS installer recovers from launchd error 5 by enabling and conditionally retrying the
  per-user service, then verifies both the loaded label and the daemon control socket.

## Validation

- Demo/browser regression suite: 31 tests passed.
- Full Rust workspace test suite passed.
- Strict Clippy checks passed for the bridge binaries and the optional whisper feature.
- Production assets and release binaries were rebuilt before deployment.
