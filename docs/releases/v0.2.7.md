# Codex App Server WebUI v0.2.7

This patch release makes remote Queue and Steer submissions eventually consistent from the first
browser interaction through app-server execution and final rollout history. It also fixes two
long-session problems: stale accepted follow-ups and large viewport jumps during live updates.

## Eventually consistent Queue and Steer

Each browser submission now receives a stable client identity before the network request begins.
That identity follows the message through the optimistic outbox, Bridge negotiation, native
app-server queue, and final history reconciliation. Repeated or retried submissions remain distinct
and idempotent instead of overwriting one another.

Pending messages keep their dashed handoff state until their user item is observed in rollout
history. An accepted Steer is no longer removed merely because its RPC returned successfully, and
native Queue entries remain visible across the brief dequeue-to-rollout gap.

## Event-driven reconciliation

The persistent WebSocket stream is now the primary update mechanism. Native `turn/*`, `item/*`,
`thread/status/changed`, and `thread/queue/changed` events schedule a local, keyed refresh of the
affected session. The 1.5-second activity poll runs only while the event stream is disconnected;
event-gap notifications still trigger a complete recovery pass.

Long sessions retain the global start index of the recent-message window. This lets Bridge match
accepted inputs against the correct rollout positions even when only the latest 128 messages are
parsed for reconciliation.

## Stable navigation and project identity

Live message reconciliation preserves visible DOM nodes and anchors only against currently visible
messages. A completed turn cannot collapse underneath the reader and move the page far upward.
Message copy controls now float at the lower-right of the text instead of consuming a separate row.

Linked worktree sessions retain their real worktree directory for execution, but their project
identity is resolved through Git's common directory. This keeps Codex-created worktrees grouped
under the same repository project instead of producing duplicate sidebar groups when app-server
does not provide a project ID.

## Protocol and upgrade

The typed Bridge protocol is version 25. Send and Steer requests accept an optional stable
`submission_id`, and pending records expose enough state for clients to reconcile negotiation and
application without maintaining a second status machine.

This is a Bridge and embedded-Web-UI hot update. The managed app-server can remain alive while the
Bridge process is replaced and adopts the existing connection.

## Validation

- The rebuilt release WASM passes all 29 browser/demo regression tests.
- The complete Rust workspace passes, including stable submission identity, accepted-Steer landing,
  recent-message cursor, linked-worktree grouping, interruption, download, and managed-runtime
  coverage.
- The production Vite bundle is embedded in the feature-complete release daemon, and the deployed
  WebSocket endpoint reports a ready event stream.
