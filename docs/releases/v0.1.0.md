# Codex App Server WebUI v0.1.0

The first public release turns a homelab, NAS, Mac mini, or Linux workstation into a responsive,
self-hosted control plane for Codex app-server. Keep Codex beside the repositories it works on,
then follow and control the same tasks from a terminal, phone, tablet, or private browser UI.

Remote-control traffic travels directly between your clients and your bridge. The Web UI does not
use the ChatGPT app as a remote-control relay; Codex app-server continues to use the OpenAI account
and network configured on the host.

## Highlights

- Create sessions in an existing project or isolated Git worktree, then rename, pin, archive, or
  stop them.
- Use a persistent app-server connection for live activity, native queue and steer handoff,
  interruption, model selection, rate limits, and bounded active-session subscriptions.
- Watch active and recently finished work in the multi-session Tasks view. It combines the latest
  prompt, agent response, tool progress, final state, and a direct session link without duplicating
  the full transcript. Long responses collapse in place.
- Inspect structured tool calls, parallel and multiline shell commands, file diffs, and workspace
  files from the shared mobile-first interface.
- Load large sessions through a low-memory rollout index that skips non-display records and reads
  tool output by offset only when requested.
- Download regular workspace files smaller than 16 MiB through five-minute, process-local tickets
  that reject paths outside the selected session directory.
- Try the real production frontend on GitHub Pages with a live Rust/WASM simulator. It selects
  template progress from each prompt and supports queue, steer, withdrawal, cancellation,
  structured tools, and simulated voice-to-text without sending messages or images off-page.
  The same contract backs automated browser-facing regression tests.

## Deployment

The user-level installers support two modes without `sudo`:

- macOS with Codex Desktop: the bridge supervises the bundled app-server and local WebSocket
  adapter under launchd.
- Linux or desktop-free macOS: the bridge supervises the standalone open-source app-server under a
  user service.

The Web UI listens on loopback by default. For remote access, keep it private behind Cloudflare
Tunnel plus Access, a VPN, or another authenticated HTTPS reverse proxy instead of exposing the
bridge port directly.

See the [installation guide](../install.md), [`codexctl` reference](../codexctl.md), and
[interactive demo](https://gh.bhee.online/codex-bridge/demo/).

## Validation

This release is checked with the Rust/WASM demo contract, the production Vite build, the complete
Rust workspace test suite, and Clippy with warnings denied. Hardware, host configuration, Codex
account access, and reverse-proxy policy remain deployment-specific.
