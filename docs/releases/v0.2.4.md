# Codex App Server WebUI v0.2.4

This release turns the local runtime into an observable managed system without coupling the
app-server lifetime to Web UI deployments. It also adds a private local speech fallback, browser
completion notifications, and fixes stale Stop state and composer caret movement.

## Managed runtime and hot deployment

In Desktop mode, `codex-bridge` can supervise the bundled app-server and loopback WebSocket
adapter from one LaunchAgent. A healthy app-server remains alive when Bridge receives `SIGTERM`;
the replacement Bridge adopts its existing Unix socket instead of starting a second writer. If
that socket later disappears, the supervisor restarts the app-server normally.

The settings panel now renders the live control, Desktop transport, and voice-transcription paths.
Each managed component reports whether it is running, externally owned, stopped, or on standby,
together with its listen endpoint, restart count, and latest startup error.

## Optional local Whisper fallback

The `whisper` Cargo feature adds an OpenAI-compatible `whisper-server` transcription backend. With
the fallback enabled, Bridge prefers native app-server transcription and starts the local server
only when the native capability is unavailable. The browser continues to receive editable text;
recordings are not submitted as message attachments.

The executable, model, language, endpoint, startup timeout, and extra arguments are configurable.
The documented default uses a multilingual whisper.cpp model and works on Mac, Linux, homelab, and
NAS installations without a cloud speech API.

## Browser notifications and reliable live state

The Web UI offers an explicit browser-notification switch. After site permission is granted, a
background or unfocused page reports completed, failed, and cancelled runs. Duplicate completion
events are suppressed, and clicking a notification focuses the page and opens that session. The
page must remain open; this release does not install a background push worker.

Thread watch now confirms cached subscriptions with an authoritative `thread/read`. An idle server
state suppresses a stale active turn left in a rollout, so the composer does not continue to show
Stop for an already-finished run.

Same-thread incremental refreshes also stop assigning the current draft back to the textarea.
This preserves focus and the insertion selection while live messages and status elements update;
draft restoration still occurs when the user actually switches sessions.
