# Codex App Server WebUI v0.3.3

Version 0.3.3 makes Desktop connection health visible and makes local service updates repeatable.
It also gives new chats without a selected project a consistent workspace layout.

## Codex GUI status

- Settings → Managed components now has a Codex GUI entry. It reports whether the launchd
  `CODEX_APP_SERVER_WS_URL` is configured and matches Bridge, whether
  `CODEX_APP_SERVER_USE_LOCAL_DAEMON` is set, and whether a Desktop-owned stdio app-server is
  running. Environment variable values are not exposed in the status response.
- The state refreshes while Settings is open, making a Desktop update that changes the launch
  environment visible without reloading the page.
- Bridge can adopt a healthy, user-owned Unix socket reached through a symlink when restarting,
  preserving the existing app-server process.

## Installation and workspaces

- The macOS and Linux installers rebuild the Web UI and deploy the Bridge binaries with
  `cargo install --locked --force`, reusing the checkout's `target` directory.
- An enabled Whisper fallback automatically includes the Cargo `whisper` feature. The macOS
  installer retains an existing Bridge LaunchAgent label, migrates an old build-artifact adapter
  path to the Cargo-installed binary, and disables an obsolete standalone WS service. Repeated
  Linux installation restarts an active user service to load the new binary.
- New projectless chats create dated workspaces with `work/` and `outputs/` directories.
- On mobile, swiping a session row reveals a direct archive action.

## Validation

- The release WASM demo, browser regression suite, production Vite build, Rust workspace tests,
  formatting checks, and installer syntax checks pass from the release source.
- A macOS Desktop deployment starts Bridge and its WS adapter from Cargo-installed binaries while
  preserving the existing app-server PID. The Codex GUI status reports a matching WS environment
  and no Desktop-owned stdio app-server in that deployment.
