# Codex App Server WebUI v0.2.10

Version 0.2.10 protects Codex rollout history from the most common dual-writer configurations.
This is especially important when installing the Bridge from inside an active Codex session or
running it as an always-on homelab service.

## Exclusive managed writer

- Bridge holds an advisory lock scoped to `CODEX_HOME` for its lifetime whenever it manages an
  app-server. A second current Bridge daemon cannot manage another writer for the same store.
- The lock file is private to the user and relies on the operating system lock, so a stale file
  after a crash does not block the next clean start.
- Distinct app-server installations that intentionally need independent writers must use distinct
  `CODEX_HOME` directories; their histories remain separate.

## Safe installation and recovery

- The macOS and Linux installers inspect the configured Codex executable for `app-server`
  processes without `--listen` before starting the service.
- When installation runs inside Codex and finds a private stdio app-server, binaries, configuration,
  and service definitions are still installed, but startup is deferred until the active Codex
  process exits.
- Existing processes are never killed by the installer. This avoids interrupting the turn that is
  performing the installation.

## Runtime containment

- The managed supervisor checks for a conflicting stdio writer before launch and every two seconds
  while running.
- If a conflict appears later, Bridge stops only the app-server child it owns and exposes the reason
  through managed component status. Management resumes after the other writer exits.
- Process inspection fails closed: if exclusive ownership cannot be verified, Bridge does not start
  another managed writer.

Older and independently launched app-servers do not participate in Bridge's advisory lock. Process
detection is therefore a safety fence, not a transactional guarantee against arbitrary external
launchers. The installation guide documents this boundary and the strict-isolation option.

## Validation

- The complete Rust workspace test suite passes, including new process-classification and
  `CODEX_HOME` writer-lock regression tests.
- macOS and Linux installer scripts pass shell syntax validation.
- Production Web UI assets, Demo WASM, and release binaries are rebuilt from the tagged source.
