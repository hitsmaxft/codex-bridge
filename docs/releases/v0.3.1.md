# Codex App Server WebUI v0.3.1

Version 0.3.1 expands the Web UI as a dependable mobile workspace for long-running Codex sessions.
It focuses on safe session ownership across multiple app-servers, richer live activity, and faster
ways to read and navigate large conversations.

## Safe session ownership

- Sessions already owned by another app-server open in a clearly marked read-only mode instead of
  competing for the active writer.
- Queue input remains available without acquiring the session writer, so work can be staged while
  another app-server continues the current turn.
- The session toolbar can explicitly release Bridge's writer lock for another app-server and
  reacquire it when the session is available again.
- Standalone app-server deployment is now the recommended default on macOS and Linux, with Desktop
  interposition documented as an advanced compatibility topology.

## Live Codex activity

- Active turns expose live token usage before completion, together with cache totals and hit rate
  in the session tools panel.
- Repeated `wait` and empty `write_stdin` polling calls appear as compact activity and keep only the
  newest snapshot instead of filling the conversation.
- Subagent activity uses named robot-labelled summaries and opens the corresponding conversation in
  the existing temporary-session reader.
- Context compaction remains visible as a dedicated conversation event.

## Reading and navigation

- Long assistant responses collapse to a readable preview with expand and collapse controls at the
  message boundary.
- Floating previous and next controls move between adjacent turn starts, including on narrow mobile
  layouts.
- Completed turns retain tool-use counts and token totals while deferring their full intermediate
  content until expansion.
- Image activity is labelled explicitly, and tool-result images retain the in-page zoom viewer.
- Multi-file edit summaries show compact relative paths, and the file preview implementation is
  loaded only when a workspace file is opened.
- Session tools can refresh the current conversation from its newest server window and clear only
  that session's browser-side message cache.

## Long-session delivery

- A routed session and project navigation initialize independently, allowing the newest bounded
  message page to appear without waiting for the full project index.
- Incremental message reconciliation preserves existing DOM nodes and the reader's viewport while
  new activity arrives.
- Versioned frontend assets use long-lived browser caching while the HTML entry remains
  revalidated, reducing repeated downloads through remote access proxies.

## Validation

- The release WASM demo and browser regression suite cover writer ownership, queue-only input,
  activity compaction, subagent conversations, long-message disclosure, turn navigation, and
  large-session paging.
- The complete Rust workspace suite and production Vite build pass from the release source.
- A real mobile-sized Chromium session loads a large rollout, displays the newest message window,
  and keeps project navigation interactive after rendering.
