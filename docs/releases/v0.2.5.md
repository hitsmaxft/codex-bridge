# Codex App Server WebUI v0.2.5

This patch release fixes two Desktop interoperability gaps in the shared app-server and new-session
worktree paths introduced by v0.2.4.

## Desktop direct thread resume

When Desktop interposition is enabled, Bridge now starts its managed app-server with the disabled
base entry `mcp_servers.codex_app={command="",enabled=false}`. Desktop supplies only an incremental
`enabled_tools` value when it connects; without the process-level base, directly resuming an
existing thread can fail until another client has populated a complete MCP transport definition.

The override is limited to Desktop interposition. Standalone app-server startup remains unchanged.

## Desktop-compatible worktrees

Bridge-created isolated sessions now use the native Codex layout
`CODEX_HOME/worktrees/<UUID>/<repository>`. Their working directory remains isolated, while the
app-server `projectId` and Web UI selection remain attached to the original project. This prevents
the worktree path from appearing as a separate project in Desktop.

Existing worktrees under `~/.codex-bridge/worktrees` are not moved or deleted by the upgrade because
they may contain active or uncommitted work.

## Upgrade note

A Bridge-only hot deployment preserves a healthy app-server process, including its existing
arguments. When upgrading from v0.2.4, fully quit Desktop and restart the exact app-server process
that owns the configured Unix socket once so the new MCP base configuration takes effect. Later
Bridge-only upgrades can preserve and adopt that corrected process normally.

## Validation

- The exact release source passes the complete Rust workspace test suite and all-target,

- Worktree creation verifies the Codex directory namespace and UUID allocation layout, then removes
  only the test worktree it created.
- The release WASM demo, JavaScript regression suite, Vite production bundle, and all-feature Rust
  release binaries build successfully.
